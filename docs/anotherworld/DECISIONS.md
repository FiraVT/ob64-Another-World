## 2026-10-31 — version numbers: 0.1.0 is the first public release

three numbers). The runtime gets it as the project version, the start screen

and `tools/release.sh` refuses a tag that is not `v` + `VERSION_TEXT`.

## 2026-10-31 — the project is named OB64: Another World

Developer decision. The fork has its own name now that it reworks the war, the
enemy commanders, the classes and the drops: **OB64: Another World**, after
Anohni's song. The series takes its titles from songs (Queen's "Ogre Battle",
"The March of the Black Queen", "Teo Torriatte (Let Us Cling Together)"), and
the developer wanted a trans artist; "Another World" also says the game is not
a straight port of the N64 release. Searches for "Another World" alone find
Eric Chahi's 1991 game, so the name is always written with the OB64 prefix.

| Place | Form |
|---|---|
| Window, start screen, overlay, README, macOS display name, web page, Android label | OB64: Another World |
| Package folder and archives (`make dist`, `release.yml`, `smoke-dist.sh`) | `OB64-AnotherWorld` |
| Packaged executable | `ob64-anotherworld(.exe)`; macOS `OB64 Another World.app` |
| Build target, development executable | unchanged: `ogrebattle64` |
| Save file, game id, stored ROM, pref dir, macOS bundle id | unchanged, so existing saves and installs keep working |

The same change fixes the macOS package layout: `SDL_FILESYSTEM_BASE_DIR_TYPE=parent`
makes SDL_GetBasePath the folder that holds the `.app`, so `make dist` now puts
`ui/` and `roms/` there instead of in `Contents/MacOS`.

## 2026-10-30 — the package ships a `roms` folder, and the RmlUi test panel is gone

Developer decision: a player only drops the USA Rev A ROM into a folder. The
package now carries an empty `roms/` beside the executable (`make dist`, with a
`PUT YOUR ROM HERE.txt`). `find_exe_roms` (`app/src/launcher.cpp`) lists every
`.z64`/`.n64`/`.v64` in `roms/` and then beside the executable, and `main.cpp`
tries each with `select_rom` until one is Rev A, so the file name does not
matter and a rev 0 dump beside it is skipped. A wrong dump used to count as an
explicit ROM and end the process before any window opened; its reason now goes
to the start screen. The start screen still appears while mods are installed
(the package carries three), with the ROM loaded and START GAME ready.
`make dist` also copies `ui/`, which it used to leave out.

The RmlUi "Phase 1" test document (`app/ui/test.rml`, F2, `OGRE_RMLUI_TEST`,
`OGRE_RMLUI_TEST_AT_MS`) is removed: it was a sample panel with made-up unit
rows. F2 is no longer a reserved key.

## 2026-10-29 — the port runs US revision 0 and revision 1, and LordlyCaliber is the content tool

Developer decision. The port is recompiled from US revision 1 (`NOBE`, header
byte `0x3F` = 1, SHA-256 `3bfbaf0a…`). [LordlyCaliber](https://github.com/rempred/LordlyCaliber)
(MIT), a mature OB64 editor, targets US revision 0 (SHA-256 `571e8339…`). Its
patched ROMs cannot run on the port: their new MIPS code is not in the
recompiled program, and the revision differs. Decided:

- The port will run both revisions (per-revision configs and recompiled code,
  revision detected by SHA-256).
- LordlyCaliber is the content editor. The port loads its project data at
  runtime and does not build its own data, art, cutscene or save editor.
- LordlyCaliber's method (generated reader lists), formats and decompiled C
  (1,102 functions, read as reference from a local clone) are reused instead
  of redoing that research.

Plan: `docs/design-ecosystem.md`.

Follow-up decision (same day): the rest of phase B is merged into phase C.
The app's insertions into generated C are one data file, `config/hooks.toml`
(27 entries), applied by `tools/apply_hooks.py` for either revision; revision 0
anchors are derived from revision 1's by the address rule in
`docs/anotherworld/notes-revisions.md`, with an explicit `anchor_rev0` for the two that the
rule cannot derive (the garrison call inside the changed mission loader, and the
training mark, whose anchor holds an address's low half). It replaces
`tools/director_hook.py`, `mission_cursor.py`, `map_cursor.py`,
`battle_ai.py`, `hd_backgrounds.py` and `njpeg_readback.py`; on revision 1 it
produces the same code. `make recomp` now re-applies the main-unit hooks, which
`make regenerate` used to lose (bank-recomp applied them, then recomp cleared
`RecompiledFuncs/`). The revision 0 executable and the app's address table wait
until they are needed.

## 2026-10-31 — The auto commander

An AI commands the player's units on the mission field
(`docs/anotherworld/design-auto-commander.md`). Developer decisions:

- The liberation result is alignment, as the field overlay shows it. The rule
  moved to `app/features/liberation.hpp` so the overlay and the AI share it.
- Units recover HP everywhere and faster in a town; the AI rests hurt units in
  held towns.
- The player takes over at any time: the setting off (F4), or any order to a
  unit. The AI never orders a selected unit.
- The AI never gives up on a strong enemy. It escalates (strategy, more units,
  training) and attacks again.
- It enters towns that start story scenes, revives at the Witch's Den, keeps
  5000 goth in reserve, and does not dispatch units. Revive and shopping wait
  on R10/R12.

- The ending setting is LIBERATE / CAPTURE / EITHER, and the boss assault
  starts by itself once no town is left (both confirmed the same day).
- (same day) The AI may know where the hidden items are. It collects them all
  before the boss, one unit per item. It uses Heal Leaf and any healing item a
  unit carries; the player chooses each unit's items in Organize. Enemy units
  keep lost HP but recover fast, so the waves are 1 game hour apart.
